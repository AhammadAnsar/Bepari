# Bepari — Architecture Decision Records (ADR-001 through ADR-010)

## ADR-001: Relational Accounting Persistence & Fail-Closed `BLOCKED_DATABASE` Gate
- **Status**: Accepted (Phase 0)
- **Context**: Accounting ledgers require atomic transactions, composite foreign keys, deferred balance constraint triggers, and row-level locking. In AI Studio Starter Tier, `cloudsql.CheckFeatureEligibility` returned `NO_VALID_PROJECT` and Firebase fallback was declined and prohibited by specification.
- **Decision**: Use PostgreSQL via `pg.Pool` and Drizzle ORM as the sole persistent datastore. When PostgreSQL environment variables (`SQL_HOST` or `PGHOST`) are absent in runtime, fail closed with HTTP 503 `BLOCKED_DATABASE`. Never substitute Firestore, `localStorage`, or in-memory mock arrays for financial persistence. Use `@electric-sql/pglite` (compiled PostgreSQL 16 engine) exclusively in automated integration test suites (`tests/phase0.test.ts`) to test real SQL migrations, triggers, and RLS policies.

## ADR-002: Modular Monolith First
- **Status**: Accepted (Phase 0)
- **Decision**: Keep React SPA + Node/Hono API in a single deployable repository with strict domain module boundaries (`src/server/modules/*`) rather than premature microservices.

## ADR-003: Single General Ledger Source of Truth
- **Status**: Accepted (Phase 0)
- **Decision**: All financial balances derive from immutable `journal_entries` and `journal_lines` where `sum(debit) == sum(credit)` is enforced both in `FinanceService` (`decimal.js`) and at PostgreSQL transaction commit via `DEFERRABLE INITIALLY DEFERRED` trigger `journal_balance_at_commit`.

## ADR-004: Versioned, Reviewed Tax Rules (No Universal 15% Assumption)
- **Status**: Accepted (Phase 0)
- **Decision**: Tax profiles default to `compliance_status = 'needs_review'`. No VAT invoice or Mushak document may be issued without an effective-dated, source-referenced, specialist-approved tax rule.

## ADR-005: Restrained Mobile-First & Desktop-Productive Bilingual UX
- **Status**: Accepted (Phase 0)
- **Decision**: Warm neutral canvas (`#FAFAF8`), white structural cards (`#FFFFFF`), evergreen primary action (`#126B58`), Bengali-first (`Noto Sans Bengali`) with English toggle, 5-destination mobile bottom bar, collapsible desktop sidebar, and zero synthetic KPI cards.

## ADR-006: Transactional Scoped Document Numbering
- **Status**: Accepted (Phase 0)
- **Decision**: Internal IDs use UUIDs; legal document numbers are allocated transactionally via row locks on `document_sequences` scoped by `(organization_id, branch_scope, document_type, fiscal_key)`.

## ADR-007: Defense-in-Depth Multi-Tenant Isolation
- **Status**: Accepted (Phase 0)
- **Decision**: Enforce tenant isolation at three layers: (1) Server session membership verification (`requireTenantPermission`) rejecting `x-organization-id` header/body spoofing (`TEN-02`), (2) Composite foreign keys `(organization_id, id)` on all tenant tables (`TEN-01`), and (3) PostgreSQL Row-Level Security (`CREATE POLICY tenant_isolation_policy`) bound to transaction-local `app.current_organization_id`.

## ADR-008: Offline Scope Restricted to Unposted Drafts
- **Status**: Accepted (Phase 0)
- **Decision**: Never allow offline financial posting or offline legal tax serial allocation.

## ADR-009: Additive Schema Migrations & Immutable Snapshots
- **Status**: Accepted (Phase 0)
- **Decision**: Track SQL migrations under `/drizzle/` with explicit forward (`0000_phase0_foundation.sql`) and rollback (`0000_phase0_foundation.down.sql`) scripts.

## ADR-010: Non-Authoritative AI Boundary
- **Status**: Accepted (Phase 0)
- **Decision**: Do not use LLM inference for ledger math, tax rates, or regulatory compliance decisions.
